# Корпоративный сервис микроблогов — Python Advanced

Автор: Станислав Смирнов. Учебный backend на FastAPI, SQLAlchemy и PostgreSQL 15; Nginx отдаёт готовый интерфейс Vue и проксирует API.

## Запуск на Windows или Ubuntu

Нужны Docker с работающим Linux engine и Docker Compose v2+. Откройте терминал в корне проекта:

```sh
docker compose up -d --build
docker compose ps
```

Миграции применяются автоматически до старта сервера. Backend ждёт готовности PostgreSQL, Nginx — готовности backend. Python и Node на компьютере для обычного запуска не нужны. Старое Windows-окружение `venv` в Ubuntu переносить не нужно.

- Приложение: http://localhost:3000
- Swagger: http://localhost:8000/docs
- OpenAPI: http://localhost:8000/openapi.json
- Проверка приложения и соединения с БД: http://localhost:8000/health

На **пустой** базе создаются демо-пользователи с ключами `test` и `colleague-key`, подписка и приветственный твит. Существующие пользователи и ключи не заменяются. Для отключения демо-данных задайте `SEED_DEMO: "false"` в environment backend. Эти открытые ключи предназначены только для локальной демонстрации.

В интерфейсе панель справа позволяет выбрать api-key. Настройка сохраняется только в текущей вкладке. Главная показывает твиты пользователей, на которых вы подписаны, по убыванию числа лайков; при равенстве — новые сначала. Если подписок нет, лента пустая. Свои записи доступны в «Профиль»; после публикации открывается ваш профиль. Чужой профиль можно открыть через аватар автора или адрес `/profile/ID`.

## Данные и резервная копия

PostgreSQL хранится в именованном томе `postgres_data`, картинки — в `static/media` на компьютере. Обычный перезапуск и пересоздание контейнеров сохраняют их. Не используйте `docker compose down -v` для базы с нужными данными. Не меняйте имя Compose-проекта при работе с существующим томом.

```sh
docker compose exec db pg_dump -U postgres -d twitter_db -Fc -f /tmp/database.dump
docker compose cp db:/tmp/database.dump ./database.dump
```

Отдельно скопируйте `static/media`. Для восстановления используйте отдельную пустую базу и `pg_restore`; не восстанавливайте поверх рабочей базы без резервной копии.

Миграция `20260922_integrity` оставляет один лайк/подписку на пару пользователей/записей и добавляет ограничения уникальности. Владельцы старых прикреплённых изображений определяются по автору твита. Старые изображения без автора нельзя прикрепить заново. Откат схемы не восстанавливает удалённые дубли: для полного возврата нужна резервная копия.

## API

Все бизнес-запросы требуют HTTP-заголовок `api-key`. Успешный ответ содержит логическое `result: true`, ошибка — `result: false`, `error_type`, `error_message`. Swagger описывает модели и коды ответов.

| Метод | Адрес | Назначение |
|---|---|---|
| GET | `/api/users/me` | Свой профиль |
| GET | `/api/users/{id}` | Чужой профиль, подписчики и подписки |
| GET | `/api/tweets` | Лента подписок; `offset`, `limit` (1–100) |
| POST | `/api/tweets` | `tweet_data` и необязательный `tweet_media_ids`; ответ `tweet_id` |
| DELETE | `/api/tweets/{id}` | Удаление только автором |
| POST / DELETE | `/api/tweets/{id}/likes` | Лайк / снятие лайка |
| POST / DELETE | `/api/users/{id}/follow` | Подписка / отписка |
| POST | `/api/medias` | Multipart-поле `file`; ответ `media_id` |

Расширение для страницы профиля: `GET /api/tweets?author_id=ID`. Параметр `skip` сохранён как совместимый аналог `offset`. Повторные лайки/подписки не создают дубли; повторное снятие допустимо. Подписка на себя запрещена. Проверяются права автора и владельца изображений. Создание твита и привязка всех изображений выполняются одной транзакцией.

Изображения PNG/JPEG/WEBP/GIF до 5 МиБ проверяются по содержимому. До 10 изображений в твите; текст — 1–10000 символов и не только пробелы. Файлы получают случайные имена. При удалении твита лайки удаляются, изображения отвязываются, но физически сохраняются; автоматическая очистка неиспользуемых файлов не реализована.

## Проверки

Тестовый образ отделён от рабочего. Тесты используют временную SQLite-базу и временный каталог картинок, рабочую БД не трогают.

```sh
docker build --target test -t diploma-tests .
docker run --rm diploma-tests pytest -q --cov=app --cov-report=term-missing
docker run --rm diploma-tests ruff check .
docker run --rm diploma-tests ruff format --check .
docker compose exec backend python -m alembic check
```

Дополнительно при ревизии проверены настоящий PostgreSQL, параллельные запросы, Nginx, новая установка, миграция резервной копии и сохранение твита с картинкой после перезапуска. SQLite-тесты сами по себе не заменяют эти проверки. Mypy пока не настроен; не заявляется полное покрытие всех сценариев.

Логи и диагностика:

```sh
docker compose logs --tail 100 backend
docker compose logs --tail 50 frontend
docker compose exec backend python -m alembic current
```

## Структура и разработка

- `app/models`, `schemas`, `crud`, `routers` — БД, модели ответов, операции, маршруты.
- `app/start.py`, `seed.py` — миграции и необязательная инициализация пустой БД.
- `alembic/versions` — история схемы; `tests` — тесты API.
- `frontend/src` — восстановленные из исходных source map и доработанные исходники учебного интерфейса.
- `materials/dist` — готовая сборка; `nginx.conf`, `docker-compose.yml`, `Dockerfile` — запуск.

Для сборки интерфейса нужен Node.js 22+:

```sh
cd frontend
npm ci
npm run build
```

Сборка обновляет `materials/dist`. Для локального Python используйте Python 3.11, виртуальное окружение, `pip install -r requirements-dev.txt`, `.env.example` как образец и отдельный PostgreSQL. Затем `python -m alembic upgrade head` и `uvicorn app.main:app --reload`. В Compose адрес БД задаётся как `db`; пароли и имя БД в этой локальной конфигурации демонстрационные. Публикуемые порты привязаны к 127.0.0.1. Для VM используйте перенаправление портов VS Code SSH (3000 и 8000).

Разделы уведомлений, сообщений, трендов и часть декоративных кнопок исходной вёрстки — макеты, они не входят в обязательный API диплома. Регистрация, редактирование профиля и твитов не реализованы. Сервис настроен для учебного локального запуска, а не публичного размещения.
